# 1. Introduction

## Philosophy of post supervision

Post supervision is risk management, not scheduling. The schedule is an output;
the actual job is moving discoveries earlier — every problem has a date on
which it becomes expensive, and the post supervisor's work is to make sure it
is found before that date.

Three principles run through this manual:

1. **Every decision lives at the gate where it is cheapest.** The project
   lifecycle has four gates, each with one owner and one verb:

   | Gate | Verb | Owner |
   |------|------|-------|
   | [G1] Before greenlight | DECIDE | producer + writer/director |
   | [G2] Before principal photography | LOCK | line producer + post supervisor |
   | [P] During production | WATCH (weekly) | post supervisor + editor |
   | [PL] At picture lock | VERIFY | post supervisor |

2. **Planning and verification are the same items at two different times.**
   A pipeline locked at G2 and never re-verified at PL is a pipeline that
   drifted during the shoot. Anything marked [G2→PL] in the audit is checked
   twice, on purpose.

3. **A checklist that can be completed by ticking boxes is reference material,
   not a tool.** Every audit ends with written answers to the Green-Light
   Review questions; every weekly review produces a change to the risk
   register, even if the change is "nothing moved."

## Why post begins in pre-production

The biggest post costs — VFX scope, ADR volume, structural re-edits, delivery
rejections — are set on the page and on the shooting plan, not in the edit
suite. By the first day of photography, most of the post budget is already
committed; it just hasn't been spent yet.

This is why the post-production audit (`docs/post-production-audit.md`) is
read in pre-production: it is the intake procedure for every project entering
the lab. No project is greenlit without its Final Green-Light Review answered
in writing.

## Typical cost multipliers

The same problem, fixed at different gates, costs an order of magnitude more
at each later gate. Rules of thumb `[CALIBRATE: replace with Argonautas

| Fix made… | Multiplier | Example |
|-----------|-----------:|---------|
| On the page (G1) | 1× | Cut the exposition scene from the script |
| In prep (G2) | 2–5× | Camera test catches a codec the pipeline can't conform |
| On set (P) | 5–10× | Reshoot an insert while the location is still dressed |
| In post (PL) | 10–50× | Build the insert in VFX; ADR the scene; retime mixed frame rates by hand |
| After delivery rejection | 50×+ | Remaster for a platform spec nobody read; festival version without textless |

The multiplier is the argument for everything else in this manual: chapter 2
standardizes pipelines so G2 locks are pre-made; chapter 3 tells each
department what to watch; chapters 4–5 price the risks; chapters 6–9 are the
memory and the forms that keep it running.
